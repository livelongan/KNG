# 批量中文化 translate-zh

目标:把用户指定的一批文件安全地翻译成简体中文,不破坏代码结构与格式,术语一致,可断点续跑。

## 0. 解析输入

- 参数 = 用户消息中除命令以外的内容(文件路径、glob、目录),多个用空格分隔。
- 没有参数时:先执行第 1 步扫描,把候选清单(按中文占比排序)给用户看,让用户确认范围。**不要未经确认就翻译整个仓库。**
- 用户消息中出现"直接执行 / 不用确认 /全自动"等表述时,跳过确认环节。

## 1. 扫描候选文件(确定性脚本)

```
node .cline/skills/translate-zh/scripts/list-files.mjs <路径或glob...>
```

- 输出 JSON:`{ count, files: [{ path, lines, bytes, hasChinese, cjkRatio }] }`。
- 脚本已自动排除 `node_modules`、`dist`、`.git`、`.env*`、lock 文件、二进制/压缩文件等。
- `cjkRatio >= 0.3` 的文件视为已中文化,默认跳过(除非用户点名要重翻)。
- 读取项目根目录 `.translate-zh-progress.md`(见第 5 步),已完成的文件跳过。

## 2. 制定批次计划

- 每批 ≤ 300 行或 12KB(取小者);单文件超限就按行号切成多段,分段翻译后拼接。
- 代码文件与 Markdown 文档分开成批。
- 开始前向用户展示计划:文件总数、批次数、每批包含哪些文件;确认后执行。

## 3. 翻译规则

### Markdown / 文本文档

- 翻译:正文、标题、列表、表格中的说明文字、图片 alt 文本。
- 保持原样:代码块(含其中注释)、行内代码、URL、文件路径、命令、HTML 标签、YAML frontmatter 的键。frontmatter 的 `title`/`description` 等**值**可以翻译。
- 保持:标题层级、列表缩进、链接目标 URL(链接文字可译,锚点不动)、原有换行。

### 代码文件(.ts/.tsx/.js/.jsx/.css/.html)

- 只翻译:**注释文字** 与 **面向用户的字符串**(UI 文案、错误/提示消息、aria-label、placeholder)。
- 禁止改动:标识符、变量/函数/类型/属性名、导入路径、API 名、代码逻辑与格式化、模板字符串中的 `${}` 表达式与占位符。
- 指令性注释保持原样:`eslint-disable`、`@ts-*`、`prettier-ignore`、`istanbul ignore`;`TODO`/`FIXME` 关键词保留,其后说明文字可译。
- UI 文案风格与项目现有中文保持一致(本项目为 MUI + 简体中文),用词遵循 docs/glossary.md。

### 通用

- 中文与英文/数字之间留一个空格;使用全角标点。
- 含义拿不准的词:在译文后用括号保留原文,不要猜。
- 编辑时先重读目标文件再写回,避免行号漂移;保持原文件的换行符风格。

## 4. 术语一致性

- 翻译前先读 [glossary.md](docs/glossary.md),按术语表执行。
- 遇到表中没有、且会反复出现的术语:译完后把「原文 → 译法」追加到 glossary.md 的「追加区」,保证后续批次一致。

## 5. 断点续跑:progress.md

- 进度文件:项目根目录 `.translate-zh-progress.md`。
- 格式:复选框列表,`- [ ] <相对路径>(批次 #n)`,完成一项立即改为 `- [x]`。
- 中断后重新运行本技能时,先读该文件,只做剩余部分。
- 全部完成后询问用户是否删除进度文件(并提示可把它加进 .gitignore)。

## 6. 校验与汇报

- 批次中改动了代码文件:运行 `npx tsc -b` 与 `npx eslint <改动的文件>`;报错必须修复后该批次才算完成。
- 纯文档批次:抽查 Markdown 结构(标题层级、代码块围栏是否完整)。
- 最终汇报:改动文件数与行数、新增术语、遗留问题;建议用户按批次 git commit。
