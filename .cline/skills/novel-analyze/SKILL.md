# 小说拆解 novel-analyze

目标:输入一本小说(.md/.txt 单文件或章节目录),**一次性直接产出 5 份分析文档**,不询问、不创作改写,只做客观分析。

## 0. 解析输入与输出目录

- 输入:一个小说文件路径,或一个章节目录(目录模式用 `node .cline/skills/novel-rewrite/scripts/list-chapters.mjs <目录>` 列出章节;脚本不存在时手动枚举)。
- 输出目录:小说文件 → 同级 `<文件名去扩展名>-analysis/`;章节目录 → 同级 `<目录名>-analysis/`。5 份文档编号命名:
  `01-大纲.md`、`02-简介与世界观.md`、`03-人物关系.md`、`04-时间线与人物弧线.md`、`05-设定集.md`,外加工作笔记 `_progress.md`。
- 用户说"直接" → 扫描结果**通报即可,直接开工**,不等确认;仅当规模 > 200 万字时建议分卷执行。

## 1. 分块粗读(核心纪律)

- 块大小以**字符数为准**:每块 ≤ 4 万字符,且 ≤ 1500 行(先到为准)。中文 txt 常有整段一行的情况,行数少不代表字数少 —— 首块先读 300 行估出平均行长,再定每块行数。read_files 单次返回上限约 4.7 万字符,不要超。章节目录:按顺序逐章读,超长章同法分段。
- **每读完一块,立即把笔记追加到 `<书名>-analysis/_progress.md`**,格式:
  `## 块 N(行 a–b / 第 x 章)` 下记:剧情要点、出场人物(新人物标注首次出现)、地点、时间线索、新设定名词、伏笔。
- 严禁不记笔记就继续读下一块;严禁跳读。笔记是后面所有文档的唯一事实来源。

## 2. 交叉核对

- 粗读完成后,用代码搜索工具按**主要人物名、地名、组织名**在原文中检索,核实关键场景与细节,修正/补记到 `_progress.md`(尤其多重身份、时间跨度、称呼变化)。

## 3. 产出 5 份文档

按 [output-templates.md](docs/output-templates.md) 的模板依次生成,全部用中文:

1. `01-大纲.md`:全书卷/部结构、主线起承转合、逐章梗概(一句话+冲突+推进)、未回收伏笔。
2. `02-简介与世界观.md`:一句话简介、200 字简介、题材标签;世界观五小节(时代背景/地理/势力组织/规则体系/核心矛盾)。
3. `03-人物关系.md`:人物速览表 + **Mermaid flowchart 关系图**(边上标关系类型:亲属/恋爱/敌对/师徒/上下级/同盟;实线=明面关系,**虚线=隐藏关系**)、**多重身份子图**(一人连多个身份节点)、阵营划分、关系明细表(注明证据章节)。
4. `04-时间线与人物弧线.md`:主时间线表(事件→章节→影响)、空间线(地点迁移链,对应事件)、每个主要人物一节:`| 阶段 | 遭遇 | 做了什么 | 导致什么 | 人物变化 |`。
5. `05-设定集.md`:力量/能力体系(等级、晋升条件、代价)、组织势力、地理场景、物品道具、规则与禁忌、专有名词表(术语→解释→首次出现章节)。

- **一致性硬要求**:人物表、关系图节点、时间线人物、设定集里的专有名词,拼写必须完全一致;五份文档数据互相对得上。
- Mermaid 语法注意:**节点 id 一律用纯 ASCII**(A、B、S1……),中文与括号一律放进双引号内的标签,如 `A["张三(主角)"]`;每份图写完自查语法(收尾校验脚本会扫 CJK 节点 id)。

## 4. 断点与校验

- `_progress.md` 兼做进度文件:粗读块逐块勾选,5 份文档每完成一份勾选一份;中断续跑时先读它。
- 收尾校验:运行 `node .cline/skills/novel-analyze/scripts/verify-analysis.mjs <书名-analysis目录>`,输出的 warnings 必须逐条修复或在汇报中说明理由;确认 5 份文档 + `_progress.md` 齐全;报告输出目录、文件清单、原稿字数与各文档规模。
