# 小说大纲 novel-outline

目标:从一句话灵感到一份"能直接照着写正文"的大纲。默认用户是零基础作者:**产出大纲的同时必须产出方法** —— 每份文档的关键小节前用 `> 📖 教学注释:` 引用块解释"这部分是干嘛的、写正文时怎么用"。方法论正文见 [beginner-guide.md](docs/beginner-guide.md)。

## 0. 解析输入

- 输入三种形态:一句话灵感("我想写古言宅斗")、素材文件(路径)、完整需求。
- 关键信息缺什么,用 ask_question 一次问齐(最多 4 问,每问给 2-5 个可选项):
  1. **题材赛道**:古言(宅斗/宫斗/种田/权谋)、现言、仙侠玄幻、悬疑等;
  2. **主角一句话**:身份 + 目标 + 最大障碍(例:"落魄嫡女想翻案,障碍是全府都是敌人");
  3. **篇幅档位**:短篇(<3 万字)/ 中篇(3-30 万)/ 长篇网文(30 万+);
  4. **结局倾向**:HE / BE / 开放式。
- 用户明确说"直接生成/随便来一个" → 跳过提问,按题材主流套路自行决定,并在汇报中列出所选默认值。
- 输出目录:`<书名>-outline/`;书名未定先取候选名,汇报时附 3 个备选书名。
- `_progress.md` 记进度:输入确认、定型结论、5 份文档逐份勾选;中断续跑先读它。

## 1. 定型(先想清楚再动笔)

- 一句话简介 ≤ 25 字:**谁 + 想要什么 + 最大障碍**。这是全书靶心。
- 题材标签 3-5 个;爽点/看点清单(打脸、虐渣、双向奔赴、身份揭露、扮猪吃虎……),**逐章大纲每章必须至少挂一个**。
- **明暗双线(默认必做)**:明线=读者看得见的爽点线;暗线=冰面下的真相线,至少**两层反转**;列出**对表点**(两线交汇章节);暗线每 3-5 章必须"露一寸",不露等于没有。
- **人物网复杂度基线**:双重身份 ≥3 组、隐藏关系 ≥3 组、镜像人物 ≥2 组、血缘暗雷 ≥1 组;反派分层(明面反派 → 白手套 → 幕后棋手);主角与至少一名重要人物互为镜像。
- **时空骨架(默认必做)**:故事内纪年体系 + 主线时间轴(卷-章-时间-年龄)+ 地理格局与人物迁徙线;逐章大纲的「时间」「地点」两列必须与之一致,防时间穿帮与场景漂移。
- 篇幅决定颗粒度:短篇 → 三幕 + 逐章;中篇 → 四幕(分卷)+ 第一卷逐章、其余卷逐章一句话;长篇 → 分卷 + 第一卷逐章、其余卷章群概览(边写边细化,网文标准做法)。
- 视角人称(默认第三人称限制视角跟随主角;双主角言情可关键章双视角交替,但**章内不切换**)。

## 2. 产出 5 份文档

按 [outline-template.md](docs/outline-template.md) 生成,全中文:

1. `01-灵感与设定.md`:一句话简介、约 200 字简介(不剧透结局)、题材标签、爽点清单、**明线与暗线**(双线一句话概括 + 暗线反转分层规划)、世界观(时代/地理/势力/规则/核心矛盾)、**人物小传表**(主角→对手→幕后棋手→关键配角,表头含"暗线身份"列:明面身份 + 暗线身份 + 欲望 + 恐惧 + 秘密 + 弧线一句话)、人物关系 mermaid 图(节点 id 纯 ASCII,中文放双引号标签;实线=明面关系,虚线=隐藏关系)。01 保留核心人物关系图;按阵营分组的全量图谱与关系演变放 05。
2. `02-主线大纲.md`:**明线与暗线**(双线定义表 + 暗线层级反转表 + 对表点表)、全书结构表(每卷:明线定位 + 暗线定位、起点状态 → 终点状态)、明线事件链与暗线事件链(**必须因果相连**,禁"然后…然后…")、感情线等副线节奏点(逐拍标注对应章节)、高潮与结局。
3. `03-逐章大纲.md`:表格式 `| 章节 | 章名 | 时间 | 地点 | 一句话梗概 | 核心冲突 | 爽点/看点 | 章末钩子 | 暗线动态 |`。**每章必填冲突与钩子,缺一项视为不合格**;「时间」「地点」两列必填,取值与 05 的时间轴、地点线一致;每章挂至少一个爽点;"暗线动态"列写一句话(露一寸/静默/对表点),伏笔相关章节以 F## 标注。
4. `04-伏笔与自检.md`:伏笔表(`| 编号 | 伏笔内容 | 埋设章节 | 回收章节 | 作用 |`,编号 F01 起,**须覆盖明暗两线**:暗线每层反转至少一条专属伏笔)、统一名表(人名/称谓/组织/地名/术语/道具的定稿拼写)、自检十问(逐问作答,必含"双线是否对表、反派是否分层、镜像人物是否成立")。
5. `05-人物图谱与时空线.md`:**人物关系图谱**(总图谱 mermaid,按阵营/势力用 subgraph 分组,节点 id 纯 ASCII、中文放双引号标签,实线=明面关系、虚线=隐藏关系,连线标注关系性质;阵营说明表;关系演变表 `| 关系 | 起点状态(章节) | 转折事件(章节) | 终点状态(章节) |`,至少覆盖主角与每个重要人物)、**时间线**(纪年体系表、主线时间轴 `| 阶段/卷 | 故事内时间跨度 | 主角年龄 | 关键事件 | 对应章节 |`、主要人物年龄对表防穿帮)、**地点线**(地理格局总览表 `| 地点 | 归属/势力 | 与主线关系 |`、逐卷主要场景表、人物迁徙路线表——迁徙必须连续有路径、可复用场景清单)。短篇可三节精简,中长篇按卷展开。
- 一致性硬要求:人名、地名、术语在 4 份文档中拼写完全一致;伏笔编号在 02/03 正文中以 F## 形式引用;每条伏笔必须有回收章节。

## 3. 校验与汇报

- 收尾运行:`node .cline/skills/novel-outline/scripts/verify-outline.mjs <书名-outline目录>`,warnings 逐条修复或在汇报中说明理由。
- 脚本额外把关双线三件套与时空两列:02 必含「## 明线与暗线」小节、03 逐章表头必含「暗线动态」「时间」「地点」列、01 人物小传表头必含「暗线身份」列、05 必含「## 人物关系图谱」「## 时间线」「## 地点线」小节且至少一张 mermaid 图(节点 id 纯 ASCII);缺任一项按 warning 修复。
- 汇报必须包含:输出目录、文件清单、总章数与预计字数(章数 × 单章字数)、3 个备选书名(如已定名则跳过)、下一步建议(从 03 的第 1 章行开始写正文)。
- 用户后续要求"开始写第 X 章"时:从 03 取该章行 + 04 伏笔表 + 01 人物小传 + 05 时空线(该章时间、地点与人物关系状态)作上下文直接开写,并沿用统一名表的拼写。
