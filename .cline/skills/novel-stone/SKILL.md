# 章回体移植重写 novel-stone

目标:把原稿小说重写成「红楼梦式」文本 —— 章回体世情小说,世界观移植到**架空**宋朝文化官僚体系。

**使用前提:仅用于用户拥有版权或已获授权的原稿。**

## 0. 解析输入

- 同 novel-rewrite:一个或多个原稿路径 + 改写需求描述(可为文件路径,可附文风样本)。
- 缺需求描述必须先问,重点问三件事:
  1. **移植深度**:只换世界观外壳,还是人物姓氏、书名一并古雅化(默认:全部古雅化);
  2. **书名**:保留原书名或自拟(如《云京记》《汴梁春》);
  3. 原稿若为第一人称,确认改为说书人全知(默认)。
- 输出目录:原稿 `xxx/` → 同级 `xxx-copy/`;`summary.md` 生成在原稿目录。

## 1. 扫描章节(确定性脚本)

```
node .cline/skills/novel-stone/scripts/list-chapters.mjs <目录或文件...>
node .cline/skills/novel-stone/scripts/list-chapters.mjs <原稿目录> <副本目录>   # 对比覆盖
```

- 自然排序、忽略 `summary.md` 与进度文件、输出 `chars` 字数;对比模式查 `missingInCopy`。
- 章节名是中文数字时排序不可靠 → 先把顺序列给用户确认;开始前确认文件数、总字数、输出目录。

## 2. 通读并生成 summary.md(核心:移植映射)

- 分批读章(每批 ≤ 6 万字符),边读边记要点;用 [stone-summary-template.md](docs/stone-summary-template.md) 生成 `[原稿目录]/summary.md`,除常规内容外**必须**产出:
  1. **改写要求**(用户原话)与改写方案(默认说书人全知视角);
  2. **移植映射总表**(全篇唯一权威对照):官制与机构 / 职业与身份 / 地名与府邸 / 名物与器物 / 称谓 / 年号纪年 —— 原稿元素 → 架空对应。**写作中遇到表外新元素:先补表,后行文**;
  3. **人物表**:原名 → 古雅化姓名 + 表字,身份官职按映射,改名对照;
  4. **回目对照表**:每回一行,原章名 → 新回目两句对仗(全书统一,重写时不自拟);
  5. 分章梗概(剧情要点、必须保留的情节点、出场人物、章尾钩子、回中诗词点)。
- 超长小说分卷更新 summary;断点续跑且 summary 已存在时不要重建,只核对与补齐。

## 3. 逐回重写

- 文件名与原稿一致;**章内首行改为章回体回目**:`第 N 回 <两句对仗>`(取自回目对照表)。
- 文体硬规则见 [stone-style-guide.md](docs/stone-style-guide.md),核心:
  - 说书人套语:话说/却说/且说起段,「正是」两句收,「且听下回分解」结尾,转场「不在话下/按下不表」;
  - 世情白描:宴饮、诗会、拜会、官场应酬等场景推动剧情;对话见性情,少心理独白;
  - 诗词穿插:每回回末两句必备,回中诗词 1–3 处按需,诗贴合情境,禁堆砌;
  - **现代词汇零容忍**:发现原稿残留概念先查映射总表,表外则补表;
  - 情节走向、章节边界、伏笔回收不变;篇幅为目标章的 80%–120%;人名官署全篇一致。
- 每回写完立即查重:
  `node .cline/skills/novel-stone/scripts/check-similarity.mjs <原章文件> <副本回文件>`
  `violationCount > 0` 改到 0;**命中公共章回套语(话说/却说/且听下回分解等)可豁免**,其余必须改写。
- **样章门槛:第 1 回完成必须暂停**,展示回目 + 开头约 500 字 + 回中诗词 + 回末套语,请用户确认「红楼味」是否对路;确认后再继续(用户明确要求"直接跑完"时跳过)。
- 每写完一回立即更新进度文件。

## 4. 进度与断点续跑

- 进度文件:`[原稿目录]/.novel-stone-progress.md`,复选框逐回勾选。
- 中断重跑:先读 summary.md 与进度文件,从首个未完成回继续;全部完成后询问是否删除进度文件。

## 5. 校验与汇报

- 对比模式脚本:`missingInCopy` 为空、`extraInCopy` 为空;`totalChars` 字数偏差 ≤ +30%(章回体诗词扩写允许略增)、≥ -20%。
- **专名一致性专项(本技能特有)**:
  - 按映射总表逐一搜索"架空名"在副本的出现次数;
  - 反向搜索映射表中"原稿元素"字样在副本的残留(残留 = 漏映射,必须处理);
  - 搜索原稿主要人名在副本的残留(改名必须彻底)。
- 抽查回目质量(两句对仗)与前后回衔接(结尾/开头各约 20 行);汇报:回数、字数对比、查重结果、映射表条目数、summary.md 位置;建议 git commit。
