# 小说改写 novel-rewrite

目标:对一批小说原稿章节做「先生成 summary.md,再逐章洗稿式重写」的批量改写,输出到副本目录。

**使用前提:仅用于用户拥有版权或已获授权的原稿。**

## 0. 解析输入

- 用户消息中包含:一个或多个原稿路径(目录或单个文件)+ 一段改写需求描述(自由文本)。需求描述也可能是 md/txt 文件路径(读取其内容作为需求),还可附**参考文风样本**文件路径(重写时模仿其句式与节奏)。
- 判定规则:消息里的路径作为参数;其余叙述文字就是改写需求描述,**原样保留**。
- 缺需求描述 → 必须先询问改写方向(视角、文风、背景、人物、情节取舍),不得自行假设。
- 输出目录:原稿目录为 `xxx/` 时,副本目录默认为同级 `xxx-copy/`;用户显式指定输出目录则用用户的。`summary.md` 生成在**原稿目录**下。

## 1. 扫描章节(确定性脚本)

```
node .cline/skills/novel-rewrite/scripts/list-chapters.mjs <目录或文件...>
node .cline/skills/novel-rewrite/scripts/list-chapters.mjs <原稿目录> <副本目录>   # 对比覆盖
```

- 列表模式输出 `{ count, totalBytes, files: [{ path, lines, bytes }] }`;对比模式输出 `{ count, copyCount, missingInCopy, extraInCopy }`。
- 自动按章节名**自然排序**(第2章排在第10章前);忽略 `summary.md`、进度文件、隐藏文件、非 md/markdown/txt。
- 章节名若是中文数字(第一章/第十章)排序不可靠 → 开始前把扫描到的顺序列给用户确认。
- 开始前向用户确认:文件数、总字数、输出目录;确认后再动笔。

## 2. 通读并生成 summary.md

- 按顺序分批读章(每批 ≤ 6 万字符),**边读边把要点追加进 summary 草稿**,避免超长小说重读。
- 用 [summary-template.md](docs/summary-template.md) 的结构生成 `[原稿目录]/summary.md`,必须包含:
  1. **改写要求**(用户原话,逐字记录)
  2. **改写方案**(视角/文风/背景/人物/情节层面的可执行规则)
  3. **人物表**(姓名、身份、性格口癖、关系;若要求改名,加改名对照列)
  4. **世界观与时间线**(设定要点、主线、伏笔 → 回收位置)
  5. **分章梗概**(每章:剧情要点、必须保留的情节点、出场人物、章尾钩子)
- 超长小说(>5 万字)分卷处理:每读完一卷就更新 summary.md 的对应小节。
- 断点续跑且 `summary.md` 已存在时:**不要重建**,只核对其与当前需求一致、按进度补齐缺失小节。

## 3. 逐章重写到副本

- 严格按章节顺序处理,每章流程:读原章 → **只定位读取 summary 对应小节**(搜索 `### 第 N 章` 所在行号区间,不整读 summary)+ 改写方案 → **全新创作** → 写入 `[副本目录]/同名文件` → **立即查重**:
  `node .cline/skills/novel-rewrite/scripts/check-similarity.mjs <原章文件> <副本章文件>`
  输出 `violationCount > 0` 时必须改写命中的雷同片段并重查,直到为 0(用户明确豁免除外);`longestCommonRun` 应 ≤ 12。
- 硬性规则见 [style-guide.md](docs/style-guide.md),核心:
  - 以梗概为骨架**重讲故事**,不是逐句同义替换;禁止与原稿出现连续 12 字以上相同的句子(人名、必需引用除外)
  - 段落组织、叙述顺序、对话呈现方式全部重新设计;篇幅为目标章的 80%–120%
  - 剧情走向、章节边界、伏笔回收位置不变;人名地名称谓全篇一致(对照人物表)
  - 输出格式跟随源文件(.md 保留标题层级,.txt 纯文本);文件名与原稿完全一致
  - 单章 > 2 万字:按场景分段重写后拼接,重写过渡句
- **样章门槛:第 1 章重写完成后必须暂停**,向用户展示样章(开头约 500 字 + 结尾约 200 字)确认文风方向;确认后再继续后续章节(用户明确要求"直接跑完"时跳过此步)。
- 每写完一章立即更新进度文件。

## 4. 进度与断点续跑

- 进度文件:`[原稿目录]/.novel-rewrite-progress.md`(与 summary.md 同处,在小说目录现场续跑),复选框列表逐章勾选。
- 中断后重跑:先读 summary.md 与进度文件,跳过已完成章节继续。
- 全部完成后询问是否删除进度文件。

## 5. 校验与汇报

- 运行对比模式脚本:`missingInCopy` 必须为空、`extraInCopy` 应为空(章节数一致)。
- 字数对比:分别对两个目录跑列表模式脚本,取 `totalChars`(去空白字符数)对比,偏差应 ≤ ±20%。
- 抽查衔接:读副本上一章结尾与下一章开头各约 20 行,判断是否顺滑;按人物表抽查改名落实情况(搜索旧名残留)。
- 汇报:章节数对比、总字数对比(原稿 vs 副本)、查重结果(违例章节数与最长雷同段)、summary.md 位置、副本目录;建议 git commit。
