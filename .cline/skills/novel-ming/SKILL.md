# 章回体移植重写 novel-ming(明兴)

目标:把原稿小说重写成红楼梦式章回体世情小说,世界观移植到**架空明朝中兴之世** —— 政治上内阁与司礼监双轨、经济上白银开海清丈、文化上书院讲学,官僚体系完备自洽。

**使用前提:仅用于用户拥有版权或已获授权的原稿。**

## 0. 解析输入

- 同 novel-rewrite:一个或多个原稿路径 + 改写需求描述(可为文件路径,可附文风样本)。
- 缺需求描述必须先问,重点问四件事:
  1. **移植深度**:只换世界观外壳,还是人物姓氏、书名一并古雅化(默认:全部古雅化);
  2. **中兴格局侧重**:开海通商 / 清丈税改 / 阁监之争,用户可指定全书主线政经议题;
  3. 原稿若为第一人称,确认改为说书人全知(默认);
  4. 书名保留或自拟(如《金陵春明录》《宝钞风云》)。
- 输出目录:原稿 `xxx/` → 同级 `xxx-copy/`;`summary.md` 生成在原稿目录。

## 1. 扫描章节(确定性脚本)

```
node .cline/skills/novel-ming/scripts/list-chapters.mjs <目录或文件...>
node .cline/skills/novel-ming/scripts/list-chapters.mjs <原稿目录> <副本目录>   # 对比覆盖
```

- 自然排序、忽略 `summary.md` 与进度文件、输出 `chars` 字数;对比模式查 `missingInCopy`。
- 章节名是中文数字时排序不可靠 → 先把顺序列给用户确认;开工前确认文件数、总字数、输出目录。

## 2. 通读并生成 summary.md(核心:移植映射 + 中兴格局)

- 分批读章(每批 ≤ 6 万字符),边读边记要点;用 [ming-summary-template.md](docs/ming-summary-template.md) 生成 `[原稿目录]/summary.md`,必须包含:
  1. **改写要求**(用户原话)与改写方案(默认说书人全知、红楼梦式世情白描);
  2. **移植映射总表**(全篇唯一权威对照):官制与机构(含宦官系统)/ **经济与商政**(货币、税制、商帮、海贸)/ 职业与身份 / 地名与府邸 / 名物与器物 / 称谓 / 年号纪年 —— **表外元素先补表后行文**;
  3. **中兴格局设定**:自拟年号(如「景隆中兴」)、内阁与司礼监力量对比、清流与实务派、厂卫权限、当前政经大事(开海/清丈/盐法),作为全书政斗剧情的背景板;
  4. **人物表**:原名 → 古雅姓名 + 表字,身份按映射(文官/宦官/勋贵/商贾/士子),改名对照;
  5. **回目对照表**:每回一行,原章名 → 新回目两句对仗(重写时不自拟);
  6. 分章梗概(剧情要点、必须保留的情节点、出场人物、章尾钩子、回中诗词点)。
- 超长小说分卷更新 summary;断点续跑且 summary 已存在时不要重建,只核对与补齐。

## 3. 逐回重写

- 文件名与原稿一致;**章内首行改为章回体回目**:`第 N 回 <两句对仗>`(取自回目对照表)。
- 文体硬规则见 [ming-style-guide.md](docs/ming-style-guide.md),核心:
  - 说书人套语:话说/却说/且说起段、「正是」两句收、「且听下回分解」结尾、「有分教」预叙;
  - 世情白描:衙署议政、票拟批红、书院讲会、盐商宴集、市井坊铺等场景推动剧情;对话见性情,少心理独白;
  - 诗词穿插:回末「正是」两句必备,回中 1–3 处按需,诗贴合情境禁堆砌;
  - **现代词零容忍**:残留概念先查映射总表,表外补表;**清制词也算穿帮**(军机处/奏折不能用,用题本/奏本/揭帖);
  - 情节走向、章节边界、伏笔回收不变;篇幅为目标章的 80%–120%;人名官署全篇一致。
- 每回写完立即查重:
  `node .cline/skills/novel-ming/scripts/check-similarity.mjs <原章文件> <副本回文件>`
  `violationCount > 0` 改到 0;**公共章回套语命中可豁免**,其余必须改写。
- **样章门槛:第 1 回完成必须暂停**,展示回目 + 开头约 500 字 + 回中诗词 + 回末套语,请用户确认文风;确认后再继续(用户明确要求"直接跑完"时跳过)。
- 每写完一回立即更新进度文件。

## 4. 进度与断点续跑

- 进度文件:`[原稿目录]/.novel-ming-progress.md`,复选框逐回勾选。
- 中断重跑:先读 summary.md 与进度文件,从首个未完成回继续;全部完成后询问是否删除进度文件。

## 5. 校验与汇报

- 对比模式脚本:`missingInCopy` 为空、`extraInCopy` 为空;`totalChars` 偏差 ≥ -20% 且 ≤ +30%(章回体诗词扩写允许略增)。
- **专名一致性专项(本技能特有)**:
  - 按映射总表逐一搜索"架空名"在副本的出现次数;
  - 反向搜索映射表中"原稿元素"字样在副本的残留(残留 = 漏映射,必须处理);
  - 搜索原稿主要人名在副本的残留(改名必须彻底);
  - 反向搜索**清制与现制词汇**(军机处、奏折、公司等)残留。
- 抽查回目对仗与前后回衔接(结尾/开头各约 20 行);汇报:回数、字数对比、查重结果、映射表条目数、中兴格局要点;建议 git commit。
